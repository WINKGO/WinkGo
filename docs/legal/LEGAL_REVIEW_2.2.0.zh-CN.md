# WINK GO 2.2.0 知识产权、隐私与发布审查

**审查日期：** 2026-07-30  
**审查对象：** WINK GO 桌面端、内置 Skills、配套移动端/小程序连接、账号与云中转接口、构建及发布材料  
**结论性质：** 工程与合规风险审查，不构成任何国家或地区执业律师出具的正式法律意见。

## 一、结论

WINK GO 2.2.0 的代码、开源许可证、第三方归属、PDF Skill、Electron 安全边界和可选云中转同意机制已经达到“可制作私有候选版本”的条件。

当前不应把托管账号服务、官方云中转或小程序作为“已经完成全球生产合规”的公共服务宣传或正式开放。发布前仍须由实际运营者补齐法定身份、地址、服务器地域、处理者/接收方、跨境机制、权利请求时限和备份删除周期，并在目标市场完成商标与上线资质核验。

任何人都无法合法保证“全世界任何律师都不能起诉”。能够做到的是保留证据、降低胜诉风险、及时处理投诉，并避免作出超过代码事实的承诺。

## 二、已验证项目

### 1. Apache-2.0 与上游归属

- 仓库保留完整 Apache License 2.0。
- `NOTICE` 和 `THIRD_PARTY_NOTICES.md` 保留 AionUI、AionCore、aionrs 的必要来源、版本、固定提交和版权归属。
- 三套固定上游清单和修改清单覆盖 2,312 个已修改文件，其中 2,143 个文件具有行内修改声明，169 个不能安全添加注释的文件使用清单记录。
- 依赖许可证归档和锁文件覆盖检查通过。
- 产品界面、项目名称和宣传材料不再把 WINK GO 表述成 AionUI，也不暗示上游赞助或背书。

Apache-2.0 第 4 条要求衍生分发保留适用的版权、专利、商标和归属声明，并在存在上游 `NOTICE` 时继续提供可读副本。因此，AionUI 等名称只能从产品品牌与宣传位置移除，不能从法定 `LICENSE`、`NOTICE`、第三方清单及必要源码修改声明中抹除。

### 2. PDF Skill

- 用户可见目录为 `backend/crates/winkgo-app/assets/builtin-skills/pdf/`，兼容性实现目录为 `pdf-toolkit/`。
- 两个目录都只包含 WINK GO 自有的 Markdown、Apache-2.0 许可证和来源记录，没有图片、二进制工具或远程执行脚本。
- `pdf` 是保持 2.1.45 技能名称的兼容入口，使用独立编写的 PDF 工作流程；没有复制旧 Skill 的文本、脚本或资产。
- PDF Skill 只描述 Poppler、qpdf、MuPDF、OCRmyPDF、Tesseract 等工具的公开命令行接口，不捆绑这些第三方程序，也不替用户自动安装。
- 资源、许可证与重复文本检查已通过。

Moltbook 技能单独保留其上游声明的 MIT 许可证、官方来源记录和外部服务提示；WINK GO 不声称拥有 Moltbook 的名称、服务、API 或上游文本。

知识画布来自本机只读历史项目中独立开发的 `wink-go-canvans` 0.1.2 源码构建，不属于 AionUI/AionCore 上游文件。安装包随画布保留源码构建哈希、React Flow 页面署名，以及 57 个实际运行时依赖对应的 25 份去重完整许可证文本。

旧 Git 历史曾包含不可随本项目继续分发的 PDF Skill。正式 WINK GO 仓库必须使用无父提交的新历史，不能把旧仓库历史合并、镜像或普通推送到新仓库。

### 3. 品牌与公开说明

- 公开产品名和版本统一为 **WINK GO 2.2.0**。
- 产品、更新、Core、Hub、安装指引和仓库元数据统一指向公开主仓库 `WINKGO/wink-go`；旧个人 GitHub 账号不再出现在源码或发行资源中。
- README 按开放、免费、公益项目介绍现有能力，不再设置公开的 Pro 功能说明或付费功能分级。
- 文档已经说明第三方模型、API、云中转、语音、消息平台和网络资源可能由相应服务商收费。
- 灵动岛、智能体、MCP、Skills、工作区、自动化、消息渠道、WebUI、小程序配对、技术架构和五项路线图均按当前实现与后续计划区分。
- README 不包含生成式宣传图片；仅保留文本、表格和架构图。

“WINK GO”仍需要在计划经营的国家、地区和商品/服务类别中进行专业商标检索。WIPO 明确建议同时检索各国家和地区注册库；仅搜索互联网或只查一个数据库不足以形成清权结论。

### 4. 登录、注册与账号安全

- 桌面端能够到达实际账号服务；无效账号返回业务错误 `invalid_credentials`，不会再被误报为普通“网络错误”。
- 登录和注册不再自动替用户开启云端设备中转。
- 账号服务代码采用密码哈希验证、令牌哈希/HMAC、限流、会话和安全事件记录；部署时仍须核验 TLS、数据库权限、密钥管理、备份和维护任务。
- 登录页在提交登录或注册前要求用户确认服务条款和隐私政策。

### 5. 云中转、隐私与移动配对

- 云中转默认关闭。
- 配置已升级到 schema 5，并记录云中转同意版本。旧版本中即使保存过 `relayEnabled: true`，升级后也会强制关闭，只有用户在当前披露下再次主动开启并保存才会恢复。
- 设置页在开关附近披露中转域名、传输的数据类别、文字/语音转写/任务结果、可能的文件与认证信息、第三方费用、跨境可能性和关闭方式。
- 配对码短时有效且一次性使用；账号、安装实例、电脑、智能体、会话和任务使用独立标识。
- 独立移动端只允许公网 WSS；明文 WS 仅允许回环或私有局域网，并显示风险提示。
- 移动 Relay 审计默认保留 30 天、最多 300 条，可在 1–365 天范围内配置；状态采用原子写入，POSIX 上目录和文件使用私有权限。
- 已删除“端到端加密”等与实现不一致的宣传表述。

桌面隐私政策已经如实列出当前账号服务的代码保留规则：非活动下载票据 30 天、非活动会话 90 天、登录安全事件 180 天、限流记录 1 天。账号、手机号、设备、绑定和同意记录目前没有自动到期删除任务，桌面端也没有自助删除账号接口，因此仍需运营者提供人工权利请求流程。

### 6. Electron、安装与供应链

- 窗口默认启用 `sandbox`、`contextIsolation` 和 `webSecurity`。
- 导航、弹窗、WebView、IPC 发送方、来源、主框架、参数结构和大小均实施限制。
- 麦克风、通知和剪贴板写入按可信主框架与用途放行；摄像头、屏幕捕获和非可信来源默认拒绝。
- Linux WebUI 不再使用 `--no-sandbox`，安装脚本创建非特权 `winkgo` 服务账号，并启用 systemd 的 `NoNewPrivileges`、只读系统和内核保护。
- OfficeCLI 安装来源改为官方仓库固定提交，下载脚本必须通过固定 SHA-256 后才可执行。
- 生产依赖安全审计、第三方许可证检查和 Electron 相关测试已通过。

## 三、正式公共运营前的阻断项

以下信息不能从代码中推断，也不能由工程人员代填：

1. 实际个人信息处理者/服务运营者的法定姓名或公司全称。
2. 可送达的注册地址或经营地址，以及所在国家、省市。
3. 正式服务器和备份所在国家/地区。
4. 云服务、短信、账号、模型、语音、日志、邮件和支付等处理者或接收方的准确名单。
5. 跨境传输适用的法律路径、单独同意或其他法定程序。
6. 访问、更正、导出、撤回同意和删除请求的确认时限、完成时限及申诉方式。
7. 备份轮换周期、删除策略、事故响应负责人和监管联系流程。
8. 目标市场的商标检索与申请结论。
9. 中国境内面向公众提供 APP/小程序或互联网信息服务时适用的备案、许可和平台材料。

在上述信息补齐前，新 GitHub 仓库、Release 和安装包应保持私有或草稿状态；不得把托管服务宣传为“已完成全球合规”。

## 四、建议的发布证据包

正式发布时至少保留：

- 最终源代码提交、标签和构建日志。
- 安装包 SHA-256、自动更新清单、签名/公证结果。
- `LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`、依赖许可证归档和上游修改清单。
- PDF Skill 的 `SOURCE.md`、重复文本检查和测试结果。
- 知识画布的 `SOURCE.md`、运行时依赖清单和完整许可证归档。
- 依赖安全扫描、秘密扫描、Electron 安全测试及隐私测试结果。
- 隐私政策、服务条款、同意版本、上线时实际数据流和供应商合同。
- 商标检索报告、备案/许可材料和投诉处理记录。
